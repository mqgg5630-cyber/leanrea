# "一直实时监控" —— 真实能做到什么，边界在哪

## 1. 我（对话里的 agent）为什么不能一直盯

- 我只在**你发消息之后的这一轮**里运行。一轮里我可以连续做事几分钟（轮询、跑
  hub 任务、等待），但**不能跨小时常驻** —— 我这条回复结束，这一轮就结束了。
- 我的沙盒在云端，**看不到你的屏幕**。我能取到的只有你机器主动写进 git 的东西。
- 所以"永不结束的实时监控"必须落在**你机器上的常驻进程**，而不是我的对话。
  这一点我已经这么做了（见下）。

## 2. 机器上现在真正常驻的东西

| 进程 / 任务 | 作用 | 状态 |
|---|---|---|
| `jev-chat-monitor`（计划任务，登录自启） | `headless_watch.py`：截微信/QQ 窗口 → 离线 OCR → 新消息写 `logs\events.jsonl` | **运行中**，已抓到 27 条真实聊天 |
| `jev-chat-analyze`（计划任务，登录自启） | `auto_analyze.py`：新消息 → 安静 25 s → **本机模型**出「意图/情绪/风险/3 条候选/推荐理由」→ `logs\live.html` | 已注册，等模型装完自动生效 |
| Ollama 服务 | 本机推理（127.0.0.1:11434），模型 `qwen2.5:3b` 塞进 GTX 1650 4 GB | 安装包分片下载中 |

**这条链完全不需要我在线，也不需要任何 API key，聊天内容不出你的机器。**

## 3. 你现在怎么用

1. 微信窗口开着（别最小化），正常聊天。
2. 对方发来一条 → 25 秒后 `E:\0apps\jev-chat-windows\logs\live.html` 里出现卡片
   （意图、情绪、风险、三条候选、为什么推荐那条）。用浏览器打开这个文件，它会每 5 秒自动刷新。
3. 我这边：你说一句"拉一下"或直接贴消息，我就把 `results/jev-monitor/` 的最新记录取上来，
   给更细的分析（小模型 3B 的判断力和我差一档，重要的对话建议以我这份为准）。

## 4. 时间表

- 安装包 1.6 GB：分片下载中（已 129 MB / 1585 MB，4 并发，约 1.2 MB/s → 还需 15~20 分钟）
- 下载完 → 静默安装 → 服务起来 → 拉 `qwen2.5:3b`（约 2 GB，registry 慢的话自动改用
  hf-mirror 的 GGUF）→ 冒烟测试 → `logs\ollama_status.json` 里 `ok: true`
- 之后 `jev-chat-analyze` 每 30 秒自检一次，模型一就绪就立刻开始分析，**不需要你再做任何操作**

## 5. 如果你希望我"整轮陪你盯"

可以：你发一句"开始盯"，我在这一轮里每 30~60 秒拉一次记录、有新消息就分析，
持续到这一轮结束（一般十几分钟）。这种方式适合"我现在就要盯着这段对话"，
不适合过夜。过夜靠的是第 2 节那两个计划任务。
